# GitHub Launch README Review

Use this review before sharing the repository publicly.

## First 30 Seconds

- [ ] The opening explains what the repo is.
- [ ] The audience is clear.
- [ ] The problem is clear.
- [ ] The reader knows what they can do today.
- [ ] The security boundary is visible early.

## Navigation

- [ ] Quick start is easy to find.
- [ ] Diagram links are easy to find.
- [ ] Docs, templates, and Ansible examples are linked.
- [ ] Validation commands are visible.
- [ ] Future paid bundle references are secondary.

## Credibility

- [ ] Claims are practical and modest.
- [ ] Examples are specific but sanitized.
- [ ] The README does not imply production readiness.
- [ ] No guaranteed job, certification, or income outcomes are implied.

## Publication Notes

The README should feel like a useful starter kit, not a sales page. The paid
bundle direction can be mentioned, but the free repo needs to stand on its own.
