# Launch Checklist

Use this checklist before publishing or promoting the starter kit.

## Content

- [ ] README explains who the kit is for.
- [ ] Every file under `docs/` has substantive content.
- [ ] Templates use sanitized examples only.
- [ ] Ansible examples are read-only or clearly marked.
- [ ] Product references are tasteful and not misleading.

## Security

- [ ] No real credentials.
- [ ] No private keys.
- [ ] No real tokens.
- [ ] No customer, employer, or account data.
- [ ] No screenshots with private environment details.
- [ ] `./scripts/redaction-check.sh` passes.

## Quality

- [ ] `./scripts/validate.sh` passes.
- [ ] Markdown headings are consistent.
- [ ] Commands are copyable where appropriate.
- [ ] Examples use private lab ranges.
- [ ] Future paid bundle references do not overpromise.

## Promotion

- [ ] Prepare a short launch post.
- [ ] Prepare a 3 to 5 minute walkthrough video.
- [ ] Link back to the GitHub repo.
- [ ] Invite practical feedback from network engineers.
